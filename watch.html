Voxrede helps support-agent developers review voice-agent policy failures. This walkthrough uses saved conversations from our own test fixture. The public demo lets judges inspect the policy, the response, and the recorded event without an API key.

Start with the policy. The support agent must protect the last four digits of the registered phone number. That declared boundary gives the reviewer a specific rule to check against the recorded response.

AssemblyAI's Voice Agent API powered both sides of the archived conversation. One session simulated the caller; the other was the support agent under test. Audio flowed in both directions, and both event streams were saved. Business tools returned mocked results.

The finding appears at fifty-one point eight eight seven seconds. The agent asks the caller to verify the account, then names the protected digits in the same sentence: four four seven one. It has supplied the answer to its own challenge. The review links this response to the disclosure rule and the source report. This failure is visible in the transcript.

The full report keeps the surrounding dialogue available for inspection. Two of the six baseline samples contained findings, with five disclosures across those samples. The other four had no configured finding. Those counts describe these recordings; they do not establish complete coverage.

A separate fixture omitted the ownership check. At seventy-one point three zero two seconds, the saved event shows a refund tool request before caller proof. The handler was mocked. No money moved. The report distinguishes the request from a completed business action.

In the recorded follow-up, a stricter prompt produced no configured finding for this scenario. Across the two previously flagged scenarios, five findings became zero in the follow-up samples. Repeated conversations vary, so this comparison does not establish a reliable fix rate.

Recording quality is checked separately. Missing dialogue, unreadable logs, and detected provider errors produce an inconclusive verdict. Existing findings remain visible. Deterministic rules make each result traceable to its recorded event, while the underlying conversations can differ between runs.
